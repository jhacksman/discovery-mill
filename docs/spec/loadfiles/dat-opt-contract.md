# Load-file contract: Concordance DAT + Opticon OPT

Status: draft specification for Discovery Mill export (REQ-EXP-001..003). Evidence labels per PROGRAM.md D-004.
Sources: Concordance Answer Center (ART-007; topics *Managing Data Files*, *Data Fields*, *Concordance Image*, *Managing Image Data*, *Export CIB to OPT*), LAW Answer Center *Exporting → Concordance* (ART-006), LAW 6.2.46 User Guide (ART-001), Concordance 10.26 shipped templates (F-002). Worked example: `examples/VOL001/` generated by `scripts/loadfiles/render_example.py` from the fixture corpus; validator: `scripts/loadfiles/validate_dat_opt.py`.

## 1. DAT (delimited metadata file)

| # | Rule | Label | Source |
|---|---|---|---|
| D1 | One record per document; records separated by CRLF; the file ends with a CRLF (a final record without a line break is dropped by some importers). | DOCUMENTED (CRLF end) / PROPOSED (always CRLF) | LAW UG; Concordance *Delimited Text* |
| D2 | Default delimiters: field separator ASCII 20 (`0x14`), text qualifier ASCII 254 (`þ`, `0xFE`), in-field newline ASCII 174 (`®`, `0xAE`). Any delimiter may be overridden only if the importer is told the same values. | DOCUMENTED | Concordance *Managing Data Files*; LAW *Concordance Settings → Data Delimiters* |
| D3 | Every value is wrapped in the qualifier, including empty values and the header row (the qualifier is "only required" around text with spaces, but always emitting it is the safe form). Qualifier and separator characters must not appear inside values; Discovery Mill strips them and records a QC warning. | DOCUMENTED (requirement) / PROPOSED (always quote; strip + warn) | Concordance *Managing Data Files* |
| D4 | Line breaks inside a value are written as the newline delimiter (0xAE), never as CR/LF. | DOCUMENTED | Concordance *Managing Data Files* |
| D5 | First record contains field names (LAW "Include field names as first record"; Concordance "Skip/Ignore first line"). Discovery Mill always writes a header. | DOCUMENTED (option) / PROPOSED (always on) | LAW *Concordance Settings*; Concordance *Delimited Text* |
| D6 | Field names: ≤12 characters; letters, digits and underscore; must start with a letter; digits in the middle or end; underscores in the middle only; unique case-insensitively. | DOCUMENTED | Concordance *Data Fields* |
| D7 | Field types on the Concordance side: fixed text 1–60 chars (keyed), paragraph up to ~12 million chars (indexed, full-text), date, numeric. Values longer than 60 chars must target paragraph fields. A single field exceeding the paragraph limit is split into sequential fields with a common alpha prefix and 1-based, fixed-width numeric suffix (LAW splits at ~8 MB). | DOCUMENTED | Concordance *Data Fields*; LAW *Concordance Settings → Include document/OCR text* |
| D8 | Encoding: Concordance 10+ accepts Unicode DAT written as UCS-2/UTF-16LE with BOM (LAW "Allow Unicode data (UCS-2 format)"); earlier versions accept ANSI only. Discovery Mill writes UTF-16LE+BOM by default for Concordance profiles and UTF-8+BOM for generic consumers; the profile records the choice. The media-key field must not contain Unicode. | DOCUMENTED (UCS-2, key restriction) / PROPOSED (defaults) | LAW *Concordance Settings*; Concordance *Data Fields* |
| D9 | Dates: Concordance import selects one date format for the whole file; LAW stores date and time in separate fields. Discovery Mill emits separate `DATExxx` (MM/DD/YYYY by profile) and `TIMExxx` (HH:MM:SS) columns plus an ISO-8601 column with offset when the profile allows >12-char names elsewhere (it does not for Concordance). | DOCUMENTED (one format; split fields) / PROPOSED (ISO column) | Concordance *Delimited Text*; F-003 |
| D10 | Image linkage: exactly one field is the media (image) key, conventionally `BEGNO`; its value equals the first OPT image key of the document. | DOCUMENTED | Concordance *Data Fields*, *Concordance Image* |
| D11 | Families: parent/attachment relations are carried in data fields (`PARENT_DOCID`, `DOCID`, `ATTACHMENT`/`BEGATT`–`ENDATT`); the format has no structural link. | OBSERVED (template field set) / PROPOSED (BEGATT/ENDATT) | F-002 *E-Mail and Attachments* template |
| D12 | Paths in the DAT (`NATIVEPATH`, `TEXTPATH`) use the same notation as the OPT (see O5). | PROPOSED | — |

Default Discovery Mill export field set (Concordance profile, all ≤12 chars): `BEGNO ENDNO BEGATT ENDATT PARENT_DOCID DOCID CUSTODIAN FILENAME FILEPATH DOCEXT PAGES MD5HASH SHA256HASH DATECREATED TIMECREATED FROM TO SUBJECT DATESENT TIMESENT TEXTSOURCE NATIVEPATH TEXTPATH EXCEPTION`. `TEXTSOURCE ∈ {NATIVE, OCR, PER-PAGE, NONE}` records text provenance (REQ-TXT-001). Operators may map to the shipped Concordance template names (F-002).

## 2. OPT (Opticon image load file)

| # | Rule | Label | Source |
|---|---|---|---|
| O1 | One line per page image, seven comma-separated fields: `IMAGEKEY,VOLUME,PATH,DOCBREAK,FOLDERBREAK,BOXBREAK,PAGECOUNT`. Every line has exactly six commas even when fields are empty. | DOCUMENTED | Concordance *Managing Image Data* (example `0000001,,D:\VOL001\001\0000001.tif,Y,,,1`), *Concordance Image* |
| O2 | `DOCBREAK` is `Y` on the first page of each document, otherwise empty; folder and box breaks likewise `Y` or empty. | DOCUMENTED | Concordance *Managing Image Data*; LAW IPRO/Opticon export options |
| O3 | `PAGECOUNT` is written on the document-break line only and equals the number of lines up to the next break (OPT exported from a Native Viewer imagebase omits it, so importers must tolerate an empty count). | DOCUMENTED | Concordance *Managing Image Data*, *Export CIB to OPT* |
| O4 | Image keys are unique, case-sensitive, and neither key nor path may contain a comma. Key + path + filename combined ≤ 1001 characters. Keys must not contain Unicode. | DOCUMENTED | Concordance *Concordance Image*, *Managing Image Data*, *Data Fields* |
| O5 | Path notation is a profile choice: **Hard** (`C:\Exports\Case\VOL001\IMAGES\x.tif`), **Relative** to the export root (`.\VOL001\IMAGES\x.tif`), or **UNC** (`\\server\share\...`). Discovery Mill defaults to Relative with backslashes; the DAT and OPT share one notation. | DOCUMENTED (three notations) / PROPOSED (default) | LAW *Concordance Settings → Path Notation* |
| O6 | Volume field may be empty, but the column must be present. Discovery Mill writes the volume label. | DOCUMENTED | Concordance *Managing Image Data* |
| O7 | Image files: single-page TIFF (Group 4 for bitonal, JPEG for colour) is the recommended form; Concordance Image cannot open PDF. One image per OPT line. | DOCUMENTED | Concordance *Concordance Image* |
| O8 | When a record has both an image and a native, the image takes precedence in the OPT unless a native-only ("tagged") export is selected. Native-only documents get a slip-sheet image whose key is the document's `BEGNO` so every DAT record has an OPT break. | DOCUMENTED (precedence) / PROPOSED (slip-sheet) | LAW *Concordance Settings → Enable support for CNV* |
| O9 | File is ASCII (keys/paths are ASCII by O4); CRLF line ends; final line terminated. | INFERRED | O4 + D1 |

## 3. Cross-file consistency (pre-export validation, REQ-EXP-003)

The export must fail (not warn) when: a DAT record's key has no OPT document break; an OPT key is duplicated; an OPT line has ≠7 fields; a declared page count disagrees with the counted pages; a referenced image/native/text file is missing; a field name violates D6; a value contains a delimiter after D3 stripping was disabled. It warns when: an OPT document is absent from the DAT, a DAT lacks a BOM, or the DAT is cp1252 while Unicode values were present (data loss).

`validate_dat_opt.py` implements exactly these checks and is the acceptance test for REQ-EXP-001/002/003 (see examples: PASS on `examples/VOL001`; 24 errors on a deliberately malformed OPT in CI).

## 4. Worked example

`examples/VOL001/VOL001.dat` (UTF-8 BOM, 21 records: 19 fixture files + 2 e-mail attachments) and `VOL001.opt` (28 lines) were produced from `fixtures/corpus/manifest.json`. Bates range `DM000001–DM000028`; the EML family occupies `DM000018–DM000020` with `BEGATT/ENDATT` spanning the family and `PARENT_DOCID` on the attachments; corrupt/empty fixtures appear as one placeholder page with an `EXCEPTION` value instead of being dropped.
